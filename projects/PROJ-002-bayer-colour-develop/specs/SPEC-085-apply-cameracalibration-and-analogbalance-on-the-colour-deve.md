# SPEC-085: Apply CameraCalibration and AnalogBalance on the colour develop

> **OUTLINE — `cycle: frame`.** This spec exists so its ID is stable and
> siblings can declare `depends_on: [SPEC-085]`. Capture **scope** (Context /
> Goal / Non-Goals) and **dependencies** only — the *approach* is designed
> just-in-time when this moves to `design`. Do not pre-design it here.

## Context

`STAGE-027` (PROJ-002), first of three. The parsed-but-unvalidated audit
(`docs/reviews/2026-11-21-parsed-but-unvalidated-audit.md`, PR 303, §3 and
§4 rank 1) found that irradiance never reads `CameraCalibration1/2` (50723/50724)
or `AnalogBalance` (50727). The DNG camera transform is
`AnalogBalance · CameraCalibration · ColorMatrix` (and the matching form on the
`ForwardMatrix` path), applied when `ProfileCalibrationSignature` is absent or
matches `CameraCalibrationSignature`.

This is the only audit gap confirmed live on held files. Per the audit's corpus
run, the Pixel 7 Pro carries `CC1 = diag(0.8594, 1, 0.3408)` and
`CC2 = diag(0.6162, 1, 0.5703)` with no signatures. The Pixel 4a and Canon 5D
Mark III carry smaller calibrations. All three colour-develop with `Ok` today,
and the 7 Pro's blue channel is uncorrected by a factor of 2 to 3. Re-measure
these values at design; do not cite them.

SPEC-035's ColorChecker ΔE oracle (STAGE-008) would otherwise measure this
error, so this spec lands first. The local Adobe `dng_validate` build applies
the calibration, so the SPEC-060 env-gated cross-check is the real-file oracle.

## Goal

Both colour develop paths apply `CameraCalibration1/2` (interpolated with the
same illuminant weight as the colour matrices) and `AnalogBalance` under the
DNG signature rule, so the held Pixel and Canon files move closer to
`dng_validate`, by an amount pre-registered at design.
