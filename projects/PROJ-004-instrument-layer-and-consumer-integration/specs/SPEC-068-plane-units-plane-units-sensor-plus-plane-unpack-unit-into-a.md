# SPEC-068: — Plane units: plane::units(sensor) plus plane::unpack_unit_into, a unit is a plane rectangle plus the bytes it needs (uncompressed row bands at whole-byte rows, strips, tiles via DEC-056's window, Compression 7 restart intervals, whole single-scan strips); unpack_into iterates the same units; any-order assembly byte-identical on every held file and tier-A layout; off-by-one-row red-proof; fuzz target; no allocation; a DEC for the unit shape and how a caller writes disjoint units into one plane safely.

> siblings can declare `depends_on: [SPEC-068]`. Capture **scope** (Context /
> Goal / Non-Goals) and **dependencies** only — the *approach* is designed
> just-in-time when this moves to `design`. Do not pre-design it here.

## Context

First spec of STAGE-020 (PROJ-004), covering monorail-000 / onyx-000 request 1
(`feedback/2026-11-11-monorail-000-requests.md`): `plane::unpack_into` is single-threaded,
and the requester wants units they can decode on their own threads.

The STAGE-020 framing probe (stage Design Notes) found the following:
- every held file has byte-aligned rows;
- the Q2M is one 47 MP uncompressed strip, which row bands can split;
- the Pixel files have 192 tiles;
- the two single-strip Compression 7 files are restart-free single scans, so one unit
  each.

The open design question is how a caller writes disjoint units, tiles included, into one
plane without `unsafe`.

## Goal

Add `plane::units(sensor)` and `plane::unpack_unit_into`. Units decoded in any order
assemble byte-identically to `unpack_into`, and `unpack_into` iterates the same units.
