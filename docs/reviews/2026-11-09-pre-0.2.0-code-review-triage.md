## Verdict table

| # | Sev | Finding | Verdict | Evidence |
|---|-----|---------|---------|----------|
| 1 | P1 | Overlapping IFD entry tables amplify a ~770 KB TIFF into ~6.3M parsed entries (~72 MiB) before any pixel budget applies | **REAL** | `walk_chain` (`src/ifd.rs:905`) only de-duplicates *identical* offsets (`visited.contains`) and caps IFD count (`MAX_IFDS = 512`, `:69`) — there is no cap on aggregate entries/bytes. `read_ifd` (`:978`) allocates `Vec::with_capacity(count)` of up to 65,535 entries per IFD, independently per distinct offset. 512 × 65,535 ≈ 33.5M entries is the theoretical ceiling; the reviewer's 6.29M figure is consistent. |
| 2 | P1 | Compression 7 binds on width × rows, drops the decoded JPEG frame, so an equal-area wrong shape (4×3 vs 3×4) returns `Ok(())` with a wrong row stride | **REAL** | `src/plane.rs:577-582`: the code comment states the row-band sizing "pins the dimensions" and the returned `Frame` is dropped. `decode_into` only checks `out.len() == X·Y` (`LjpegPlaneWrongLength`), which is an area check, not a shape check. For Nf=2 the effective width is `X·Nf` after column de-interleave, so the comparison must use that. |
| 3 | P1 | `OpcodeList2` payload is dropped; colour develop ignores all three lists; mono helpers use `find_map` (first match only) | **REAL** | `Sensor.opcode_lists: [bool; 3]` is presence-only (`src/ifd.rs:685-687,1708-1714`); only lists 1 and 3 keep bytes. `src/color.rs:255` documents that opcode lists "are not applied on this path". A DNG that *requires* an unsupported correction gets a plausible image and `Ok(())`. Note this overlaps the earlier-deferred "opcode handling" notes — the new point is the *silent* success. |
| 4 | P1 | `cargo deny check licenses` passes with a GPL dev-dependency; the real manifest's license listing omits `toml` and `ssimulacra2` | **REAL — confirmed locally** | `cargo deny list` on the real root prints only `irradiance@0.1.1` (Apache-2.0 / MIT). The CI job (`.github/workflows/ci.yml:142-149`) runs the same command, and `deny.toml` `[graph]` sets `all-features = true` but nothing that brings dev-deps into the evaluated graph. ## What this changes

- **0.2.0 is held** until the four P1s are fixed (maintainer decision pending — see below). Verdict on the reviewer's call: agree; #1–#3 are silent/robustness failures at the public boundary, #4 is a gate that does not check what the policy says.
- **None of the P1s touch the shipped corpus.** Both held Compression-7 files and the Bayer corpus decode bit-exact; these are hostile-input / unsupported-input behaviours, same class as the PROJ-003 close triage's "latent" findings.
- **Overlap with prior triage:** P1 #2 and #3 sit next to the earlier "unexercised-sof3-paths-garble-silently" signal (`Hi/Vi ≠ 1`, restart intervals). Plan them with that hardening scope rather than as unrelated work.
